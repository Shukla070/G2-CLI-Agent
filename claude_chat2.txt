What sandbox.py actually does:

Sandbox.create(root) — captures and resolves the workspace root once, refuses to construct on a missing/non-directory root.
sandbox.resolve(raw_path: str) -> Path — the single choke point every tool will call. Validates in order: empty → null byte → backslash → UNC → drive-letter → absolute → per-segment ../~ → then joins against root, resolves symlinks, and checks containment via Path.relative_to. Raises SandboxViolationError with a stable Reason enum (not just prose), so callers and tests can assert on why, not just that.

What the 43 tests actually prove, grouped:

Valid relative paths, including ones with .. as a filename substring (file..with..dots.txt) rather than a path segment — these must not be rejected, and weren't.
Every malformed/absolute/drive-letter/UNC/home-expansion case, including the sneaky ones: ~root (tilde+username, no separator) and a ~ segment mid-path, not just at position zero.
.. traversal rejected on syntax alone, even for notes/../output/x.txt which would land back inside root after normalization — we don't try to be clever about where it lands, we just refuse the syntax.
Symlink escapes — the category string-only validation always misses: a symlink as an intermediate directory segment, and a symlink that is the final target, both pointing outside root. Both caught because containment is checked after Path.resolve() follows the symlink.
A symlink pointing inside root is correctly allowed (sandbox restricts location, not symlink use itself).
The exception message doesn't leak the resolved outside-path back to the caller — verified by asserting the secret path string isn't a substring of the error text.

One honest note, not a hidden gap: TOCTOU (a symlink swapped in between resolve() returning and the caller's actual file operation) is a real, documented residual risk. It's in the module docstring, and I'm not going to over-engineer against it — that's disproportionate for a local single-user CLI tool, consistent with what we agreed in the design doc.
