🔴 Issues Blocking Conversation
Issue 1: Orchestrator is single-turn, not a loop
The 
orchestrator
 (run_turn) does one API call, processes tool blocks, and returns. There's no loop:

It calls the API once (line 52)
Processes tool_use blocks from the response
Returns the raw tool output string
It never feeds tool results back to the model to get a natural language answer
The assignment requires a tool_use → tool_result → ... → finalize_response loop where the model chains tool calls and eventually produces a human-readable answer. Right now the model calls list_directory, the orchestrator runs it, and returns the raw listing to the user — the model never sees the result and never synthesizes an answer.

Issue 2: finalize_response is never handled as a terminal
The orchestrator processes finalize_response the same as any other tool — runs _finalize_response() which returns a debug string like "decision_type=inform; confidence=NONE; content=...". It should extract the content field and return it as the agent's actual answer.

Issue 3: max_tokens is set to 256
In 
client.py:52
, max_tokens defaults to 256. That's far too small for the model to reason, chain tools, and produce a real answer. Should be 4096 minimum.

Issue 4: System prompt is too thin
The 
prompt
 is 6 lines. It doesn't:

Explain the available tools or how to use them
Tell the model it MUST call finalize_response to end every turn
Explain the [DOCUMENT CONTENT] wrapping defense
Explain confidence levels or when to use each
Mention the workspace structure
The system prompt template at agent/prompts/system_prompt.md exists and is much richer, but it's not being used — render_prompt() builds the prompt inline.

Issue 5: tool_choice is set to "auto" instead of "any"
In 
orchestrator.py:56
, tool_choice is {"type": "auto"}. The architecture doc says it should be "any" — forcing the model to always call a tool (including finalize_response to end a turn). With "auto", the model might respond with plain text, bypassing the confidence system entirely.

Issue 6: Conversation history isn't sent to the API
The orchestrator sends only the current user message to the API (line 54: messages=[{"role": "user", "content": user_message}]). Previous turns are appended to the session but never included in the API call, so the model has no memory of the conversation.

Issue 7: CLI --interactive position bug
In 
cli/main.py:67
, the --interactive check is after the default mode output, so you always see the confidence banner and menu before the loop starts. Also, the --new and --resume flags don't connect to the interactive loop — it always creates a fresh session.
